# תוכנית V2 — הרחבות אחרי ה־MVP

ה־MVP (שלבים 1–7) מאפשר למפעיל להשכיר סוכנים **בתוך האתר שלו**. ב־V2 הסוכנים יוצאים החוצה: לאתרים ולמערכות של הלקוחות, לערוצי הודעות ולעבודה מתוזמנת. הסדר נקבע לפי ערך עסקי מול סיכון. כל שלב יכלול אפיון קצר, בדיקות (יחידה, E2E ו־axe), עדכון מסמכים משפטיים ו־Checklist, ו־commit נפרד.

## V2.1 — API ציבורי, מפתחות API ו־Widget

**User stories**
- כמשתמש (או לקוח עסקי) אני יוצר מפתח API ומפעיל סוכן מהמערכת שלי.
- כמפעיל אני מטמיע סוכן באתר חיצוני בשורת `<script>` אחת, עם דומיינים מורשים.
- כמפעיל אני רואה שימוש ועלויות לכל מפתח, וחוסם מפתח בלחיצה.

**API (גרסה `v1`, JSON, מתועד ב־OpenAPI 3.1)**

| Endpoint | תיאור |
|----------|-------|
| `GET /api/v1/agents` | סוכנים זמינים למפתח |
| `POST /api/v1/conversations` | שיחה חדשה עם סוכן (`agent`, `input`, `fields`) |
| `POST /api/v1/conversations/{id}/messages` | הודעת המשך |
| `GET /api/v1/conversations/{id}` | מצב ותשובות |
| `GET /api/v1/runs/{id}/events` | SSE (הזרמה) |
| `POST /api/v1/approvals/{id}` | אישור או דחייה של פעולה |
| `DELETE /api/v1/conversations/{id}` | מחיקה |

**החלטות**
- **מפתחות:** `ra_live_<id>_<secret>`. נשמר רק hash מסוג SHA-256 של הסוד, והמפתח מוצג פעם אחת. הרשאות (scopes): `agents:read`, `conversations:write`, `approvals:write`. אפשר להגביל לסוכנים מסוימים.
- **בעלות וחיוב:** כל מפתח שייך למשתמש. החיוב עובר דרך הארנק הקיים (holds ו־settle), ומגבלות היום והקצב חלות כרגיל. כך אין מסלול שעוקף את החיוב.
- **Widget:**
  - מפתח *publishable* (`ra_pub_…`) שמוגבל לסוכן אחד ולרשימת Origins.
  - משתמש אנונימי מקבל session קצר מבוסס token, ולא עוגיות של האתר המארח.
  - הממשק נטען ב־iframe מבודד (`/embed/{agent}`), נגיש, עם RTL וללא עוגיות צד שלישי.
  - החיוב על חשבון בעל המפתח.
- **אבטחה:**
  - אימות בכל endpoint. בדיקת בעלות בתוך השאילתה (BOLA), כמו היום.
  - מגבלת קצב לפי מפתח ולפי IP, ומגבלת גודל payload.
  - CORS רק ל־Origins שהוגדרו ב־Widget. ה־API עצמו לא נגיש לדפדפן.
  - Audit ליצירה, שימוש ראשון וביטול של מפתח.
- **פרטיות:**
  - בעל המפתח הוא אחראי השליטה (controller) על המידע שהוא שולח. צריך להוסיף סעיף לתנאים ולמדיניות. **דורש בדיקה משפטית.**
  - ה־Widget לא מוסיף עוגיות למלאי.

**סכמה:**
- `ApiKey`: id, userId, name, prefix, hash, scopes, agentIds, kind (`secret`/`publishable`), origins, lastUsedAt, expiresAt, revokedAt.
- `Conversation.source`: `web` / `api` / `widget`.

**בדיקות:** חוזה ה־API מול OpenAPI, BOLA בין מפתחות, CORS, חיוב, מגבלת קצב, axe ל־Widget ב־RTL ו־LTR.

## V2.2 — משימות מתוזמנות וטריגרים
- **תזמון:** משימה = סוכן, קלט קבוע ולוח זמנים (cron עם אזור זמן). רצה על BullMQ job schedulers. התוצאה נשמרת כשיחה, ואפשר לשלוח אותה במייל או ב־webhook.
- **טריגר נכנס:** כתובת webhook ייחודית לכל משימה, עם HMAC (אותו פורמט כמו ה־webhooks היוצאים). התוכן הנכנס עובר ולידציה ומגבלת גודל.
- **הגנות:** מגבלות למשתמש (מספר משימות, תדירות מינימלית), קרדיטים מראש, עצירה אוטומטית אחרי 3 כישלונות ברצף, ופעולות עם אישור נשארות ממתינות.

## V2.3 — ערוצים
- **ממשק אחיד:** `Channel` (סוג, הגדרות מוצפנות, סוכן). מזהה המשתמש בערוץ מקושר לחשבון דרך קוד חד־פעמי.
- **Telegram:** Bot API עם webhook ו־secret token.
- **WhatsApp:** Meta Cloud API, אימות `X-Hub-Signature-256`, תבניות למסרים יזומים וחלון של 24 שעות. **דורש אימות מול התיעוד הרשמי של Meta בזמן הבנייה.**
- **אימייל נכנס:** IMAP או webhook של ספק הדואר.
- **פרטיות:** מספרי טלפון ומזהים הם מידע אישי. צריך לעדכן את מפת המידע, ההסכמות, ה־DPA מול Meta ואת זכויות המחיקה. **דורש בדיקה משפטית.**

## V2.4 — Evals
- **מערך בדיקה לכל סוכן:** קלטים, וציפיות כמו "מכיל" / regex / JSON schema, או שופט מודל עם קריטריונים.
- **הרצה:** על טיוטה לפני פרסום, עם השוואה לגרסה הנוכחית (ציון, עלות וזמן). אפשר לחסום פרסום מתחת לסף.
- **מקור הבדיקות:** דירוגים שליליים של משתמשים הופכים למקרי בדיקה, רק באישור ועם התממה.

## V2.5 — Router ו־Supervisor
- **סוכן־על:** "כלי" שמפעיל סוכנים אחרים מרשימה מאושרת.
- **מגבלות:** עומק (2), מספר קריאות ותקציב קרדיטים משותף לכל העץ. Trace אחד לכל העץ.
- **Router:** בחירת סוכן לפי כוונת המשתמש בקטלוג, עם הסבר שקוף למשתמש.

## V2.6 — Sandbox
- **בידוד:** קוד רץ בקונטיינר נפרד עם gVisor (`runsc`). אין רשת, יש מגבלות CPU, זיכרון וזמן, ומערכת הקבצים לקריאה בלבד חוץ מ־`/tmp`. החלופה היא Firecracker (בידוד חזק יותר, תפעול מורכב יותר).
- **דפדפן:** Playwright ב־sandbox, עם יציאה דרך ה־SSRF guard הקיים בלבד.
- **התקנה:** אופציונלי (`COMPOSE_PROFILES=sandbox`), ונבדק בהתקנה שה־runtime קיים.
- **בדיקות:** בדיקת חדירות ייעודית **חובה** לפני הפעלה ללקוחות.

## V2.7 — לפי ביקוש
- BYOK: משתמש מביא מפתח AI משלו. המפתח מוצפן, השימוש לא מחויב בקרדיטים, ונקבעת מדיניות מודלים.
- תפקידים מותאמים: הרשאות גרנולריות מעל המערכת הקיימת.
- Plugins: כלים ארוזים עם manifest והרשאות.
- Helm chart ל־Kubernetes.
